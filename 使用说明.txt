时间转换 · macOS 原生应用

1.2.1 更新：修复新增字段弹窗切换应用后变白；切换时保留已填写内容，字段校验错误直接在原表单中显示。

双击“时间转换.app”运行。可以把应用拖到“应用程序”文件夹，或保留在 Dock，方便随时打开。
无需联网、浏览器、AI 服务或额外运行环境。

在 UTC 或 GMT+8 任意一侧粘贴时间，另一侧实时换算。多条时间每行一条，空行保留。
可以只输入日期或部分时间，缺少的部分自动按 0 补齐：
2026-10-25 → 按 2026-10-25 00:00:00 换算
2026-10-25 20 → 按 2026-10-25 20:00:00 换算
2026-10-25 20:30 → 按 2026-10-25 20:30:00 换算
完整输入支持 YYYY-MM-DD HH:mm:ss，也兼容 HH-mm-ss；日期与时间之间可以使用 T。
日期与时间各部分依然需补齐位数：日期 YYYY-MM-DD，时/分/秒各 2 位。
输出、当前时钟和复制统一为 YYYY-MM-DD HH:mm:ss。
GMT+8 固定比 UTC 快 8 小时，自动处理跨日、跨月、跨年和闰年，不受电脑时区或夏令时影响。
不存在的日期会提示行号；全部修正后恢复复制功能。

MySQL 时间筛选条件
1. 字段下拉默认包含 created_at、updated_at；点 + 新增自定义字段，例如 paid_at、orders.created_at。
2. 类型可以选择 string、datetime、date；每个字段的类型分别保存，重启后保留。− 只移除选中的自定义字段。
3. “取值”默认使用另一侧转换结果，也可固定使用 UTC 或 GMT+8；预览旁会显示实际采用的时区。
4. 未手动选模板前，单条时间默认 >=，两条默认半开区间，更多条默认 IN；手动选择后记住该模板。可选 =、>、<=、<、<>、BETWEEN、>= 且 <。
5. 范围模板输入两行，依次为起始和结束时间；BETWEEN 包含两端，半开区间不包含结束时间。
6. 预览随输入实时更新；点击“复制 SQL”或按 ⇧⌘ Enter，然后粘贴到 MySQL 的 WHERE 后。
7. 这里只生成筛选条件片段，不包含 WHERE、表名或分号，不连接或执行数据库。

值类型示例（取值时间 2026-10-27 08:00:00）
string：`created_at` >= '2026-10-27 08:00:00'
datetime：`created_at` >= CAST('2026-10-27 08:00:00' AS DATETIME)
date：`created_at` >= CAST('2026-10-27' AS DATE)
date 类型先按所选时区换算，再只保留日期；MySQL date/datetime 值使用 1000—9999 年。
字段支持最多三段名称（如 db.orders.created_at），自动逐段添加反引号。
参考 MySQL CAST 官方文档：https://dev.mysql.com/doc/refman/8.4/en/cast-functions.html

快捷键
⌘ Enter：复制另一侧的转换结果
⇧⌘ Enter：复制 MySQL 时间筛选条件
⌘ 1：选中 UTC 输入
⌘ 2：选中 GMT+8 输入
⌘ N：在最后编辑的一侧填入当前时间
⇧⌘ K：清空两侧
⌘ W：关闭窗口，应用仍在菜单栏运行
⌘ Q：彻底退出
⌘ C / V / Z：复制、粘贴、撤销，使用 macOS 标准行为

菜单栏会出现 UTC ⇄ 8，点击后可重新打开窗口。
勾选“窗口置顶”，可以边看其他应用边换算。
不会自动开机启动；退出后不保留输入的时间。

构建
源码保留在 Sources/；使用系统的 Swift 和 AppKit，无第三方依赖。
在此目录运行 bash build.sh，会先执行转换测试，再生成当前 Mac 架构的原生 .app。
当前构建面向 macOS 13 及以上系统。
